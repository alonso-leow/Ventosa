# Choosing motion tools and quality gates (K-animlib)

For motion sources (HyperFrames, web inserts, any HTML or React render). The house catalogue `K-animations` comes first.

## Pick the tool
| Need | Tool |
|---|---|
| Timelines, scroll or sequence control | GSAP |
| Simple, small effects | Anime.js |
| React-native motion, springs | Motion |
| Smooth scrolling (web inserts) | Lenis with GSAP |
| SVG morph or path animation | GSAP or Anime.js |
| 3D with animation | three.js driven by GSAP (see `K-3d`) |
| Vector or geometric shapes | SVG, or Canvas 2D when many |
| Generative, fractal, flow-field art | Canvas 2D or p5.js |
| Audio-reactive | Web Audio / Tone.js |
| Physics | Matter.js |
| Per-character type effects | GSAP SplitText with Canvas |
| Glitch | CSS layers with clip-path, driven by GSAP |
| Hard brutalist cuts | raw CSS steps |
| Quiet minimalist motion | Motion springs |

## Style feel
Brutalist: abrupt, no easing, mono type. Minimalist: slow, smooth, light type. Abstract: noise- and parameter-driven. Neo-brutalist: bold but controlled, mono plus colour.

## Easing
Smooth ease-out for most things; snappy for UI; slight overshoot for playful; strong in-out for drama. Durations: micro 150-300 ms, UI 300-500 ms, section change 500-800 ms, stagger 20-100 ms per item.

## Gates
1. Animate transform and opacity only. 2. `will-change` sparingly. 3. Clean up every timeline and listener. 4. Scope selectors to a container. 5. Memoize variant objects. 6. 60 fps. 7. Respect reduced motion in interactive pages. 8. At most 3 flashes per second in any motion source. 9. In a seek-based renderer, every animation must be a pure function of time (no wall-clock timers, no CSS transitions).
Typical bugs: smooth-scroll not tied to the scroll plugin, missing scope, double effects under React strict mode, no refresh after dynamic content.

## Ready-made component kits
Copy-in kits (shadcn-style registries, animated-background and text-effect collections) save time for backgrounds, text reveals, marquees, counters. Record each file's licence in `<ID>-sources.md`. Prefer plain CSS/SVG/Canvas when a dependency would be the only reason a render fails. Typical failures: missing peer packages, keyframes not added to the stylesheet, stacking-order clashes, too many animated layers (cap particle counts, pause off-screen), styles not generated by the CSS framework.
